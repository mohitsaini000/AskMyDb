Under the hood

Four steps. One of them is AI.

01

You ask, in plain English

No SQL required. The question goes in exactly as you'd say it to a colleague.

02 — the one AI hop

The model drafts SQL, grounded in your real schema

Spring AI reads your live table and column names via JDBC and hands them to the model with the question — so it can't invent a column that doesn't exist.

03

A guardrail checks it before anything runs

SELECT-only, no destructive keywords, no stacked statements, an automatic row limit. Nothing the model writes touches the database unchecked.

04

Postgres runs it — real rows, not a guess

The query executes against live data. The answer you see is what the database actually returned, every time.
